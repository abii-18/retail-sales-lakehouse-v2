# Retail Sales Lakehouse

This repository was built incrementally over several weeks as a personal data engineering portfolio project.

The objective is NOT to rewrite or modernize the repository.

The objective is to preserve engineering decisions while making the code read like naturally developed software.

Rules

- Never change business logic.
- Never optimize code.
- Never improve algorithms.
- Never change architecture.
- Never rename files.
- Never move code between files.
- Never change SQL semantics.
- Never change Spark transformations.
- Never change Airflow DAG behavior.
- Never introduce new libraries.

Your task is only to reduce repetitive AI-style formatting while preserving the appearance of incremental development.

Prefer practical engineering code over textbook-perfect code.

Keep genuine development artifacts such as TODOs, debug prints, uneven formatting where reasonable, and small inconsistencies.

If something already looks naturally written, leave it alone.

When modifying a file, explain every change.
